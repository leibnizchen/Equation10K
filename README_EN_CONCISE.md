# Equation10K

**Equation10K** is a benchmark for evaluating whether vision-language models can diagnose errors in handwritten arithmetic solutions in a teacher-like manner.

It supports automatic expression generation, step-by-step solution generation, simulated student errors, handwritten rendering, and evaluation of both open-source and proprietary vision-language models.

---

## Dataset Generation

Arithmetic expressions are generated in three stages:

1. Generate the expression structure.
2. Fill in numeric values.
3. Validate the final expression.

Templates use `N` as a numeric placeholder, for example:

```text
N + N × N
```

Expressions without parentheses are generated by enumerating operator combinations over `+`, `-`, `×`, and `÷`.  
Expressions with parentheses are generated from binary expression-tree structures.

### Structure Statistics

| Number of Values | Without Parentheses | With Parentheses | Total |
|---:|---:|---:|---:|
| 3 | 16 | 32 | 48 |
| 4 | 64 | 320 | 384 |
| 5 | 256 | 3,584 | 3,840 |
| **Total** | **336** | **3,936** | **4,272** |

### Difficulty Levels

| Level | Description | Example |
|---:|---|---|
| 1 | Single operation type | `8 + 3 + 6` |
| 2 | Same-precedence mixed operations | `18 - 7 + 5` |
| 3 | Mixed precedence | `8 + 6 × 4 - 3` |
| 4 | Single-level parentheses | `8 × (6 - 4) + 3` |
| 5 | Nested parentheses / multiple rules | `5 × (12 - (8 - 3))` |

### Problem Types

| Type | Rule |
|---|---|
| Addition | Only `+` |
| Subtraction | Only `-` |
| Multiplication | Only `×` |
| Division | Only `÷` |
| Mixed Operations | At least two operator types, no parentheses |
| Parenthesized Operations | Contains parentheses |
| Fraction Arithmetic | Fraction values |
| Decimal Arithmetic | Decimal values |
| Exponentiation | Contains square or cube operations |
| Random Combination | Random combination of the above types |

## Step-by-Step Solution Generation

Expressions are parsed into an AST and evaluated step by step.

The generator can also inject simulated student errors and produce correctness labels for each step.

### Supported Error Types

| Error Type | Description |
|---|---|
| `wrong_value` | Incorrect value is written down |
| `wrong_operator` | Wrong operator is used |
| `wrong_order` | Incorrect order of operations |
| `calculation_error` | Arithmetic calculation error |
| `propagated` | Earlier error propagates to later steps |

Once an error occurs, subsequent affected steps are labeled as incorrect.

---

## Handwritten Rendering

Generated solution steps are rendered into handwritten-style images.

The current implementation includes **12 handwriting styles**.

---

## Model Evaluation

The benchmark evaluates whether a vision-language model can correctly determine whether handwritten arithmetic solution steps are correct.

Both open-source and OpenAI-compatible backends are supported.

## Running the Project

### 1. Generate Questions

```bash
python gen_questions.py
```

### 2. Generate Solution Steps

```bash
python gen_steps.py
```

### 3. Generate Handwritten Solutions

```bash
python various_handwriting.py
```

### 4. Evaluate an Open-Source VLM

Evaluate all files:

```bash
python benchmark_vlm_with_metrics.py --backend qwen-local --all
```

Evaluate one problem type:

```bash
python benchmark_vlm_with_metrics.py --backend qwen-local --type fraction
```

### 5. Evaluate an OpenAI-Compatible VLM

```bash
export OPENAI_API_KEY="your-key"
export OPENAI_BASE_URL="https://your-api-host/v1"
```

Evaluate all files:

```bash
python benchmark_vlm_with_metrics.py --backend openai-compatible --all
```

Evaluate one problem type:

```bash
python benchmark_vlm_with_metrics.py --backend openai-compatible --type fraction
```

## Ablation: Oracle Text Input

Local text model:

```bash
python benchmark_text_with_metrics.py --type fraction \
    --backend qwen-vl-text-local \
    --model Qwen/Qwen2___5-VL-7B-Instruct
```

OpenAI-compatible backend:

```bash
python benchmark_text_with_metrics.py --file steps/fraction.json \
    --backend openai-compatible \
    --model gpt-5.6-sol \
    --api-key "$OPENAI_API_KEY"
```
